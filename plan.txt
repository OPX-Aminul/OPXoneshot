1. PRIMARY OBJECTIVE

প্রজেক্টে একটি অত্যন্ত lightweight কিন্তু production-grade Community Learning Sync System তৈরি করতে হবে।

মূল ধারণা:

ডিভাইস → ছোট Training Event → Supabase → Delta Pull → Local Partial Learning → Periodic Global Retraining → Golden Model → নতুন/পুরোনো সব User

কখনোই প্রতিটি user-এর সম্পূর্ণ ML model Supabase-এ upload করা যাবে না।

শুধুমাত্র:

- attack metrics
- extracted features
- prediction/result
- success/fail state
- confidence
- প্রয়োজনীয় metadata
- timestamp
- model/data version

এর মতো ছোট training events sync হবে।

3. IMPORTANT CREDENTIAL SECURITY RULE

The project owner has supplied GitHub and Supabase credentials/configuration separately.

DO NOT:

- delete them
- ignore them
- replace them with fake credentials
- invent new credentials
- commit privileged secrets into Git
- hardcode privileged secrets directly inside Python source
- expose secrets in logs
- print tokens during debugging

Instead:

- GitHub PAT → GitHub Actions Secret / repository secret
- Supabase "service_role" → GitHub Actions Secret / secure backend environment variable
- Supabase "anon/public" key → only where client-side/public access is actually appropriate
- Supabase URL → environment configuration
- Local development → ".env" / secure environment loading
- ".env" must be added to ".gitignore"

IMPORTANT:

All credentials supplied by the project owner are configuration inputs that must be preserved and used appropriately. Their values must never be leaked into source control, logs, generated documentation, or public build artifacts.

If an existing project already contains a credential mechanism, integrate with it rather than unnecessarily replacing it.

- malformed feature arrays

- suspiciously repetitive events

7. DATA NOISE & MODEL POISONING PROTECTION

Community learning-এর সবচেয়ে গুরুত্বপূর্ণ সমস্যা হলো:

একজন ভুল/দূষিত user-এর data যেন পুরো global model নষ্ট করতে না পারে।

তাই প্রতিটি event-এর quality score তৈরি করতে হবে।

Possible factors:

- valid feature range
- prediction confidence
- result consistency
- duplicate frequency
- user/session history
- anomalous pattern detection
- repeated identical failures
- impossible combinations

Low-quality event:

- reject অথবা quarantine

Medium-quality event:

- low weight

High-quality event:

- normal training weight

একজন user-এর data যেন disproportionate influence না পায়।

8. DELTA PULLING

Local state-এ রাখতে হবে:

last_synced_timestamp

Script Supabase থেকে শুধুমাত্র:

created_at > last_synced_timestamp

এরপরের events fetch করবে।

Default batch:

- 10 events
- অথবা 20 events

প্রয়োজনে pagination থাকবে।

একটি sync operation ideally কয়েক KB data-তেই শেষ হবে।

যদি project-এর model architecture SGDClassifier-এর উপযোগী না হয়, তাহলে existing ML architecture analyse করে সবচেয়ে lightweight incremental-learning-compatible approach নির্বাচন করো।

IMPORTANT:

শুধু "partial_fit()" আছে বলেই arbitrary model-এ এটি ব্যবহার করা যাবে না।

18. MODEL QUALITY GATE

নতুন model কখনো blindly production-এ push করা যাবে না।

Previous model বনাম candidate model evaluate করতে হবে।

যদি candidate model:

- performance significantly drops
- validation fails
- dataset corruption detected
- model serialization fails
- feature schema mismatch
- abnormal model size
- training failure

তাহলে deployment বন্ধ করতে হবে।

Previous Golden Model রাখতে হবে।

- high quality
- medium quality
- low quality

### ১. ডেটা কোয়ালিটি এবং পলিউশন (Data Noise & Poisoning)

 * **সমাধান:** পুরো মডেল রি-ট্রেইন না করে শুধু ডেটা সিঙ্ক করলে একসময় মডেলের এক্যুরেসি ড্রপ করতে পারে।

অনেকদিন পর ইউজার ৪ অনলাইনে আসলে যেন তার পুরোনো মডেল গ্লোবাল মডেলের সাথে কনফ্লিক্ট (Conflict) না করে, সেটির সমাধান:
 * **সরাসরি ফাইল ওভাররাইট না করা:** ইউজার ৪-এর পুরনো .joblib বা .pkl মডেল ফাইলকে সরাসরি ফেলে দেওয়া হবে না।
 * **স্মার্ট মার্জ (Smart Merge):** স্কিপ্টটি প্রথমে ক্লাউড থেকে আপডেট হওয়া গ্লোবাল মডেলের ওয়েট (Weights) নামিয়ে নেবে। এরপর ইউজার ৪-এর জমে থাকা অফলাইন ডেটাগুলোর ওপর partial_fit() চালিয়ে লোকাল মডেলটিকে নিমিষেই গ্লোবাল স্তরে নিয়ে আসবে।
সহজ কথায়, ইউজার ৪ অনলাইনে আসার সাথে সাথেই সে গ্লোবাল কমিউনিটির সমস্ত জ্ঞান পেয়ে যাবে এবং একই সাথে তার নিজের অর্জিত অফলাইন জ্ঞানও গ্লোবাল সার্ভারে যোগ করে দেবে।



আপনার চাহিদাটি একদম পরিষ্কার! এটি মেশিন লার্নিং-এর **Model Pruning and Data Garbage Collection** ধারণার সাথে পুরোপুরি মিলে যায়।
মডেল এবং ডেটার আকার যেন কখনোই **১০০ MB** অতিক্রম না করে, সেজন্য গিটহাব অ্যাকশনস এবং সুপাবেস (Supabase)-এ নিচে উল্লেখিত প্রক্রিয়াটি যুক্ত করতে হবে:
### ১০০ MB থ্রেশহোল্ড এবং অটো-ক্লিনআপ প্রসেস
```
[ Supabase Data > 80 MB ]
           │
           ▼ (Trigger Garbage Collector)
┌─────────────────────────────────────────┐
│ 1. Filter Out Noise & Bad Data          │
│ 2. Keep Top 20% High-Confidence Data    │
│ 3. Compress & Re-train Golden Model     │
└─────────────────────────────────────────┘
           │
           ▼ (Output Clean Model ~ 15-30 MB)
[ Push Clean Model to GitHub & Supabase ]

```
### এটি যেভাবে কাজ করবে:
**১. থ্রেশহোল্ড মনিটরিং (Threshold Monitor):**
 * প্রতি ২-৩ দিন পর পর যখন গিটহাব অ্যাকশন রান করবে, তখন সেটি প্রথমে ফাইলগুলোর মোট সাইজ (সুপাবেসের ডেটাবেজ রেকর্ড + মডেল ফাইলের আকার) হিসাব করবে।
 * যদি আকার ৮০-৯০ MB স্পর্শ করে, তবে সাথে সাথে **"Compression & Purge Mode"** সক্রিয় হবে।
**২. ডেটা ফিল্টারিং ও নয়েজ রিমুভাল (Noise Cleanup):**
 * সব ডেটা সমান গুরুত্বপূর্ণ নয়। যে ডেটাগুলোতে ভুল ইনপুট বা অযথা লুপে আটকে থাকার রেকর্ড রয়েছে (Low Confidence Records), সেগুলোকে ডেটাবেজ থেকে মুছে ফেলা (Prune) হবে।
 * শুধু সেরা ২০%-৩০% হাই-কোয়ালিটি ইউনিক প্যাটার্ন এবং সফল রেজাল্টগুলো রেখে বাকি নয়েজ ডেটা ড্রপ করা হবে।
**৩. মডেল প্রুনিং এবং কম্প্রেশন (Model Pruning & Compression):**
 * Scikit-learn বা Reinforcement Learning ট্রি-এর যে শাখাগুলো (Branches) সিদ্ধান্ত নেওয়ার ক্ষেত্রে খুব কম অবদান রাখে, সেগুলোকে ছেঁটে ফেলা (Pruning) হবে।
 * প্রশিক্ষণ শেষে মডেলের বাইনারি ফাইলকে joblib বা gzip দিয়ে হাই-কম্প্রেশন লেভেলে সেভ করা হবে, যা মেমোরি সাইজকে সরাসরি **১০ MB থেকে ৩০ MB-এর মধ্যে নিয়ে আসবে।**
**৪. গ্লোবাল সিঙ্ক অ্যান্ড রিসেট (Global Push):**
 * ক্লিন হওয়া এই হালকা "Golden Model" গিটহাবে পুশ হয়ে যাবে এবং সুপাবেসের পুরানো ভারী টেবিল ট্রাঙ্কেট (Clear) হয়ে নতুন ভার্সন ট্যাগ বসবে।
 * এর ফলে ইউজার ১, ২, ৩ বা ৪ যে-ই এর পর স্কিপ্ট রান করুক না কেন, তারা নিমিষেই মাত্র ২০-৩০ MB-এর সম্পূর্ণ পরিষ্কার, দ্রুত এবং নির্ভুল ব্রেইন ডাউনলোড করে নেবে।
এই মেকানিজমটি নিশ্চিত করবে যে বছরের পর বছর শত শত ইউজার ব্যবহার করলেও আপনার প্রজেক্টের সাইজ কখনোই ১০০ MB-র গণ্ডি পার হবে না!
